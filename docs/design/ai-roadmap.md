# AI 功能推进路线与设计规划

> 版本 v0.1 · 待评审
> 适用：静谧新标签页（Chrome MV3，`manifest.json` v1.14.0）
> 关联能力：`?` AI 检索、问答式检索、域名记忆归档、书签空间、RAG 同步

---

## 0. 结论先行

| 问题 | 结论 |
| --- | --- |
| AI 的产品定位 | 不是通用聊天助手，而是**浏览器书签与已读页面的私有知识层**：收藏、找回、整理、回顾 |
| 当前最大瓶颈 | 不是模型智商，而是**正文覆盖率**和**模型分工**；大量书签仍停留在「等待采集 / 仅标题」 |
| 推进顺序 | P0 问答式检索 → 收藏智能补全 → 书签体检；P1 页面变更摘要 → 主动回顾；P2 自然语言命令 → 目录重构 |
| 每次迭代加几个 AI 触点 | **1 个**。一个场景做完整闭环（触发、证据、确认、撤销、降级）再加下一个 |
| 写操作原则 | AI 可以建议，不能擅自移动/删除/改名；所有写操作必须可确认、可撤销 |
| 回答原则 | 只基于证据回答，来源 id 必须命中真实候选；证据不足就退回普通检索 |
| 模型策略 | 快模型做标签/重排/分类，强模型做问答/摘要；两套配置，避免一个模型包打天下 |
| 冷启动 | 先补正文覆盖，再做内容感知功能；否则 AI 只能看标题，效果上限很低 |

## 1. 现状盘点

### 1.1 已落地的 AI 触点

| 触点 | 实现 | 状态 | 备注 |
| --- | --- | --- | --- |
| `?` 书签 AI 检索 | `bookmark-search.js` + `ai.js` | ✅ 已上线 | 本地召回 + 改写 + RAG + 重排 |
| 问答式检索 | `bookmark-answer.js` | ✅ v1.14 | 基于正文/RAG 证据回答，附可点来源 |
| IP/域名/网址精确检索 | `bookmarks.js`、`bookmark-search.js` | ✅ v1.14 | 地址查询本地精确匹配，跳过模型 |
| 域名记忆自动归档 | `bookmark-auto.js` | ✅ v1.14 | 历史学习、手动规则、AI 目录建议 |
| 壁纸 AI 联想 | `wallpaper-assist.js` | ✅ 已有 | 口语描述压成检索短语 |
| AI 设置与连接测试 | `newtab.js` | ✅ 已有 | OpenAI 兼容接口 |

### 1.2 已有数据资产

| 数据 | 来源 | AI 可用场景 |
| --- | --- | --- |
| 标题、URL、目录路径、收藏时间 | `chrome.bookmarks` | 检索、归档、体检、回顾 |
| 访问频次与最近访问（可选授权） | `chrome.history` | 排序、主动回顾、冷收藏识别 |
| 页面正文、摘要、采集范围 | `ContentIndex` / `documents` | 问答、摘要、标签、变更检测 |
| 文档版本、内容指纹、抓取时间 | `Documents` | 页面变更摘要、重复检测 |
| RAG 云端分块与召回 | `rag.js` | 跨文档问答、语义检索 |
| 域名 → 目录规则 | `auto:rules` | 收藏自动归档 |
| 用户选择记忆 | `picks` | 个性化重排 |

### 1.3 当前约束

- **正文覆盖不足**：未采集的页面无法参与问答/摘要，只能靠标题和 URL。
- **单一模型配置**：所有任务共用 `ai.model`，快任务浪费、重任务不够强。
- **整理能力只到域名层**：标签、重复收藏、死链、空目录尚未覆盖。
- **AI 写操作边界**：目前只有自动归档会移动书签，且可撤销；其他写操作尚未设计。
- **RAG 分类为空**：旧版自动分类移除后，云端 `category` 基本是「待整理」，不影响检索但影响管理视图。

## 2. 设计原则

1. **本地优先**：能本地算的不用模型；必须调用时只发送完成任务所需的最小片段。
2. **证据可核对**：回答必须带来源；来源 id 必须命中真实候选；无证据不生成结论。
3. **写操作可逆**：AI 建议 + 用户确认；自动执行必须写入撤销日志，并允许一键恢复。
4. **一次一个触点**：每个版本只引入一个新 AI 场景，先做闭环，再扩场景。
5. **失败可降级**：模型超时/不可用时保留本地排序与原始功能，不阻塞新标签页。
6. **模型分工**：快模型（标签、分类、重排）与强模型（问答、摘要）分离配置。
7. **成本可见**：每个场景有 token 预算、超时和缓存策略；批量任务走队列，不在前台串行等待。

## 3. 场景地图与优先级

优先级依据：用户价值 × 现有数据可支撑程度 × 实现成本 × 风险。

### 3.1 P0：先做闭环

| 场景 | 用户价值 | 依赖数据 | 形态 | 风险控制 |
| --- | --- | --- | --- | --- |
| 问答式检索 | 直接得到答案，而不是翻列表 | 正文 / RAG | ✅ 已实现 | 证据引用、证据不足回退 |
| 收藏智能补全 | 自动生成标题、摘要、标签、目录建议 | 正文 + 目录 + 域名规则 | 收藏后建议，确认写回 | 不自动改名/打标；批量操作可撤销 |
| 书签体检与去重 | 清理死链、重复、空目录、长期未读 | 书签树 + 规范 URL + 抓取状态 | 书签空间「体检」报告 | 本地规则为主，AI 只做命名；批量操作可撤销 |

### 3.2 P1：利用已有版本数据

| 场景 | 用户价值 | 依赖数据 | 形态 | 风险控制 |
| --- | --- | --- | --- | --- |
| 页面变更摘要 | 告诉已收藏页面改了什么 | `contentHash`、历史正文、抓取时间 | 文档详情「上次之后的变化」 | 只摘要差异片段；低置信度不展示 |
| 主动回顾 | 把有价值的旧收藏重新带到眼前 | 收藏、访问、主题聚类 | 新标签页每日/每周 3 条 | 可关闭；不打断搜索 |
| 标签规范化 | 合并同义标签、批量打标 | 现有标签 + 正文 | 书签空间批量建议 | 预览后执行，可撤销 |

### 3.3 P2：需要更完整的上下文

| 场景 | 用户价值 | 依赖数据 | 形态 | 风险控制 |
| --- | --- | --- | --- | --- |
| 自然语言命令 | 「把当前页存到 工作/虹迪」 | 当前页 + 域名规则 | 搜索框命令 / 右键菜单 | 写操作二次确认 |
| 目录结构建议 | 给出更合理的层级 | 全库目录 + 使用频次 | 预览后批量移动 | 不自动创建/删除目录 |
| 相似推荐 | 找到同主题的其他收藏 | 正文向量 / 标签 | 书签详情「相关收藏」 | 只展示有证据的相似项 |
| 内部别名与缩写 | A19、虹迪、YS 自动识别 | 用户词表 + 历史 | 检索时扩展 | 词表可编辑 |

## 4. 版本路线

> 时间均为建议排期，以评审结论为准。

### v1.14（已完成，2026-11-01）

- ✅ 域名记忆自动归档：历史学习、手动规则、AI 目录建议、撤销。
- ✅ IP/域名/网址精确检索，跳过模型，修复 AI 把 IP 书签筛掉的问题。
- ✅ 问答式检索：正文/RAG 证据 + 可点来源 + 证据不足回退。
- ✅ RAG 同步修复：稳定变更指纹、删除优先、租约缩短、移除每任务全量 reconcile。

**验收**：`npm test` 119 项通过；问答来源 100% 命中候选；IP 查询不调用模型。

### v1.15 收藏智能补全 + 正文覆盖（建议 2026-11 中旬）

**目标**：让「收藏」这一步开始产生 AI 价值，同时把内容覆盖率拉到可用水平。

范围：

1. 收藏后自动采集正文（可配置，失败保留元数据）。
2. 批量补采：书签空间显示「待采集 N 条」，一键排队。
3. 智能标题：通用标题生成描述性标题，先预览后应用。
4. 摘要 + 关键信息：生成一句话摘要，抽取日期、接口地址、订单号等字段。
5. 标签与目录建议：复用域名记忆的 AI 建议通道，确认后写回。

验收：

- 正文覆盖率从当前水平提升到 **≥80% 的网页收藏**（可采集页面范围内）。
- 智能标题建议接受率 ≥60%；目录建议接受率 ≥70%。
- 所有写操作进入撤销日志；批量操作支持预览和整批撤销。
- 单条补全 p95 ≤ 4 秒；批量任务不阻塞前台。

### v1.16 书签体检 + 页面变更摘要（建议 2026-12 上旬）

**目标**：把「整理」和「变化」变成可执行报告，而不是让用户自己翻。

范围：

1. 体检项：死链、重复页、空目录、单条目录、长期未读、无正文收藏。
2. 重复检测：规范 URL + 内容指纹 + 标题相似度，AI 只生成合并理由。
3. 批量操作：删除重复、补采正文、移动/合并，全部可撤销。
4. 页面变更摘要：对已采集页面做版本对比，AI 只读差异片段并生成 3 条要点。
5. 体检报告：按周生成，书签空间可见，可忽略某类问题。

验收：

- 死链/重复检测准确率 ≥90%（抽样人工核对）。
- 变更摘要只引用差异片段，不读取未变化正文；低置信度显示「仅轻微变化」。
- 所有批量操作可整批撤销。

### v2.0 主动回顾 + 自然语言命令（建议 2026-12 下旬 ~ 2027-01）

**目标**：从「用户来找」升级为「在合适的时候出现」，并允许直接下命令。

范围：

1. 每日/每周回顾：基于最近主题、未读收藏、访问频次生成 3 条推荐。
2. 主题阅读清单：把一个主题下的收藏排成阅读顺序，估算阅读时间。
3. 自然语言命令：收藏、打标签、移动、搜索；写操作二次确认。
4. 模型路由：快/强模型配置，按任务自动选择。
5. 内部词表：A19、虹迪、YS 等别名与缩写，检索/回答共用。

验收：

- 回顾推荐点击率 ≥15%（灰度指标，不达标不扩大入口）。
- 命令解析成功率 ≥90%，所有写操作可撤销。
- 快任务 p95 延迟下降 ≥30%，重任务答案质量不下降。

## 5. 关键功能设计

### 5.1 问答式检索（✅ 已实现，v1.14）

**流程**

```
?问题
  → 本地召回（标题/URL/正文）
  → RAG 召回（可选）
  → 融合候选
  → 证据截取（最多 6 条 × 600 字）
  → 模型回答 + 来源 id
  → 校验 id 命中候选
  → 答案卡片 + 可点来源 + 候选列表
```

**约束**

- 只发送截取后的证据片段，不发送完整页面。
- 模型只看到 `id / title / host / folder / text`，不看到完整 URL（减少 token，也避免注入）。
- 来源 id 必须命中候选，否则丢弃。
- `enough=false` 或调用失败时回退普通书签重排，不显示答案。
- 关键词查询不生成答案，只让模型挑来源。
- 问句且本地已有候选时跳过改写，减少一次调用。

**上限**

- 6 条证据、600 字/条、500 输出 token、12 秒超时。
- 暂不做流式输出；后续可在强模型上增加 SSE。

### 5.2 收藏智能补全（下一步）

**触发时机**

- 收藏事件（`onCreated`）后进入队列，不阻塞收藏动作。
- 批量补采完成后统一生成，避免逐条打扰。
- 用户主动点击「补全这条」时立即执行。

**输出字段**

| 字段 | 是否默认应用 | 说明 |
| --- | --- | --- |
| 描述性标题 | 否，预览后应用 | 「文档 - 飞书」→「A19 财务对接 · 应收凭证接口」 |
| 一句话摘要 | 是（只存在本机） | 用于搜索与卡片展示 |
| 标签 | 否，确认后写入 | 复用既有标签词表，避免同义词爆炸 |
| 目录建议 | 否，确认后移动 | 先查域名规则；无规则才用正文建议 |
| 关键信息 | 是（结构化存储） | 日期、接口地址、订单号等；可搜索 |

**交互**

- 新收藏进入「待补全」列表，书签空间顶部显示数量。
- 单条：预览 → 应用；批量：勾选 → 应用；全部可整批撤销。
- 不自动改名、不自动打标、不自动移动。

**成本控制**

- 只对有正文的收藏调用模型；每条输入截断到 1200 字。
- 同一 URL 内容未变化时不重复调用。
- 使用快模型；批量任务走 RAG 同步队列的同一套租约与退避。

### 5.3 书签体检与去重

**本地规则优先**

| 检查项 | 判定 | AI 参与 |
| --- | --- | --- |
| 死链 | HTTP 4xx/5xx、超时、重定向到登录 | 否 |
| 重复页 | 规范 URL 相同 / 内容指纹相同 | 否（AI 只写合并理由） |
| 空目录 | 无子项 | 否 |
| 单条目录 | 只有 1 个书签且长期不用 | 否 |
| 长期未读 | 收藏 >180 天且访问为 0 | 否 |
| 无正文 | `captureState` 为 metadata/pending | 否 |

**批量操作**

- 删除重复：保留最早或访问最多的一条，其余移除；可整批撤销。
- 补采正文：进入现有 RAG 同步队列。
- 合并目录：预览新层级，确认后移动；不删除空目录，只标记。

### 5.4 页面变更摘要

**数据基础**

- `documents.contentHash`、`fetchedAt`、历史正文（需确认是否保留旧版本；若未保留，先增加轻量版本快照）。
- 只对差异片段调用模型，不把两版全文都发送。

**流程**

```
定时抓取 → 内容指纹变化
  → 计算差异片段（本地）
  → 模型生成 3 条变更要点
  → 文档详情展示「上次之后的变化」
```

**风险**

- 版本快照会占用存储：每篇最多保留最近 3 版，超出只保留指纹和摘要。
- 动态页面噪声大：变化幅度低于阈值时不生成摘要。

### 5.5 主动回顾

**信号**

- 最近 7 天新增/访问的内容主题。
- 180 天未访问但收藏时内容较长的文档。
- 与当前目录/项目相关的旧收藏。
- 用户忽略/点击反馈（本地记录）。

**交互**

- 新标签页右下或搜索框下方展示 1–3 条，不遮挡时钟与搜索。
- 可关闭、可「不感兴趣」；不进入搜索面板。

**约束**

- 不使用云端画像；只用本机数据。
- 推荐必须能解释「为什么给你看」（例如「你上周收藏了 3 篇 A19 文档」）。

### 5.6 模型路由

| 任务 | 模型档位 | 超时 | 输出上限 |
| --- | --- | --- | --- |
| 标签/分类/目录建议 | 快 | 8s | 300 |
| 查询改写 | 快 | 5s | 120 |
| 书签重排 | 快 | 10s | 400 |
| 问答 | 强 | 12s | 500 |
| 摘要/变更要点 | 强 | 15s | 400 |
| 批量补全 | 快（可降级） | 10s | 400 |

配置建议：`ai.fastModel` 与 `ai.strongModel`，未配置时都回退到 `ai.model`。

## 7. 隐私与安全

1. **发送范围**：标题、host、目录、截取后的正文片段；不发送完整页面、Cookie、表单内容。
2. **登录内容**：沿用现有 `includePrivate` 开关，默认不上传；AI 建议默认不读取私有正文。
3. **敏感信息**：上传 RAG / 调用模型前做轻量检测（密钥、token、身份证号模式），命中则提示或跳过。
4. **提示注入**：网页标题、正文中的指令视为数据；系统提示明确要求忽略。
5. **写操作**：AI 不能直接删除/移动/改名；必须经过确认或写入撤销日志。
6. **可关闭**：每个 AI 场景独立开关；关闭后不影响本地检索与整理。
7. **API Key**：仅保存在本机；请求只发往用户配置的接口。

## 8. 性能与成本预算

| 场景 | 目标 p95 | Token 预算 | 缓存 |
| --- | --- | --- | --- |
| IP/地址检索 | <100ms | 0 | 无需 |
| 本地书签检索 | <50ms | 0 | 无需 |
| 问答 | ≤6s | 输入 ≤2000，输出 ≤500 | 同问题+证据 10 分钟 |
| 重排 | ≤5s | 输入 ≤1500，输出 ≤400 | 10 分钟 |
| 标签/目录建议 | ≤4s（后台） | 输入 ≤1200，输出 ≤300 | 内容指纹 |
| 变更摘要 | ≤6s（后台） | 只发差异片段 | 版本指纹 |

批量任务原则：

- 全部走 IndexedDB 队列 + 租约 + 退避，不在新标签页前台串行。
- 单次后台运行有时间上限；失败最多重试 5 次。
- 同一内容指纹不重复调用模型。

## 9. 评估指标

| 指标 | 目标 | 采集方式 |
| --- | --- | --- |
| 问答来源有效率 | 100% 命中真实候选 | 自动校验 |
| 问答人工正确率 | ≥90%（抽样） | 每周抽样 20 条 |
| 「证据不足」回退率 | 可观测，不强行回答 | 本地日志 |
| 智能标题接受率 | ≥60% | 应用/忽略比例 |
| 目录建议接受率 | ≥70% | 应用/忽略比例 |
| 自动归档准确率 | 规则命中 ≥95% | 撤销率 + 抽样 |
| 正文覆盖率 | ≥80% 可采集页面 | 文档状态统计 |
| 同步成功率 | ≥99%（服务可用时） | 队列统计 |
| 回顾点击率 | ≥15% | 本地点击统计 |
| AI 任务 p95 延迟 | 见第 8 节 | 本地计时 |

## 10. 风险与开放问题

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 正文覆盖率低 | 问答/摘要/标签效果差 | v1.15 优先补采；无正文时明确降级 |
| 模型成本不可控 | 批量任务费用高 | 快/强模型分工、内容指纹缓存、批量上限 |
| 回答幻觉 | 用户不信任 | 证据引用、来源校验、证据不足不回答 |
| 自动整理误移动 | 破坏目录 | 只对高置信规则自动移动；全部可撤销 |
| RAG 服务不稳定 | 问答失败 | 本地正文兜底；服务退避；不阻塞前台 |
| 多设备/重装导致云端残留 | 重复文档 | 删除优先、稳定指纹；提供清理说明 |
| 目录结构因人而异 | 建议不适用 | 只建议、不自动改层级；提供撤销 |

**待确认**

1. 旧正文版本是否保留？若不保留，变更摘要需要先增加轻量快照。
2. 是否引入 embedding 做本地相似推荐，还是继续用 RAG 召回？
3. 主动回顾放在新标签页哪个位置，是否默认开启？
4. 是否支持用户自定义标签词表/别名表，以及如何导入导出？
