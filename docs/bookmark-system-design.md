# 收藏、个人称呼与知识检索：系统业务设计

> 版本 v1.1 · 2026-11-02 · A–D 已落入工作区，验证记录见第 11 节
> 设计核对基线：扩展 v1.16.0；代码已按下文工作包改造。本地测试与线上验收分开记录。
> 范围：普通搜索、@、/、?、采集、整理、RAG 与备份之间的业务关系。

## 1. 业务目标与主场景

用户收藏网站后，应能用网站名称、自己惯用的叫法或内容找到它。系统负责采集与建议；用户负责个人命名、组织习惯及上传授权。

主场景：网页标题是“企业协同服务平台”，用户平时叫它“007”。用户保存别名 `007` 和个人说明“公司内部入口，办理报销和请假”后，即使网页摘要从未出现 007、网站需要登录或采集失败，也能通过 `@007` 找到入口。网页重采不得抹掉用户称呼。

业务承诺：

1. 保存书签后，本地标题和网址查找可用，不等待 AI、整理确认或云端。
2. 人工名称、别名、说明独立持久化；自动采集和 AI 建议不能覆盖。
3. 正文可用且满足上传策略后自动入库，不等待用户确认目录、标题或标签。
4. 临时采集失败保护历史成功正文；确认失效、撤销授权或删除最后引用时才按规则清理云端。
5. 能找到入口不代表有网页正文；回答必须遵守证据来源边界。

| --- | --- | --- |

## 3. 四种输入的业务契约

| 输入 | 用户意图 | 范围及结果 |
| --- | --- | --- |
| 普通文本 | 搜索互联网 | 维持当前搜索引擎行为 |
| @007 | 打开我认识的地方 | 本地人工入口与系统候选；不依赖正文、AI 或 RAG；打开明确选择项 |
| /007 | 在收藏里找 | 书签加同目标个人信息；没有对应书签的快捷入口不混入 / |
| ?007 怎么报销 | 找入口并解释内容 | 先定位目标；有获准正文才回答流程，无正文只给入口和证据不足说明 |

“快捷标签”是入口对象，“分类标签”是内容属性，不能混用。@ 不负责模糊猜站点；? 不因识别出内部代号就获得额外上传授权。

## 4. 信息分层与所有权

| 信息 | 所有者 | 用途 | 自动覆盖 |
| --- | --- | --- | --- |
| 书签标题、URL、目录 | 浏览器书签与用户授权操作 | 原始收藏事实 | 标题建议需确认；移动按本次采纳或已确认规则 |
| label 快捷名称 | 用户 | 个人展示名，如“公司平台” | 禁止 |
| aliases 别名 | 用户 | 简称和内部代号，如 007、OA | 禁止 |
| note 个人说明 | 用户 | 自己如何使用入口 | 禁止 |
| 网页标题、描述、正文 | 采集器 | 页面内容和来源证据 | 可刷新；临时失败不得覆盖成功内容 |
| AI 摘要、建议名称/标签 | AI，标记建议来源 | 理解和整理建议 | 可重生成，不能写回人工字段 |
| 分类与归档规则 | 用户采纳/显式编辑 | 主题与后续自动归档 | 服从人工保护与修正 |
| 收录决策、云端收据、任务 | 策略与同步引擎 | 应否上传、实际结果、执行进度 | 各自更新，不混作内容 |

删除快捷入口不删除书签；云端知识失效不删除浏览器书签；清空学习数据不删除人工信息。采纳归档建议还会建立后续自动规则，界面须展示规则范围、提供关闭和撤销，不把一次移动默认为无提示的永久授权。

## 5. 目标关联与最小数据模型

首期复用 QuickTags 人工记录，不新建重复的网站档案库。在 `newtab.tags.v1` 的版本化数据中扩展 note、updatedAt，保留 label、aliases、url、id、顺序与使用记录；存储键名称不等于数据版本号。

共享检索读模型按需关联人工记录与已有书签/文档，供 /、? 使用，不将个人信息复制到 pages.text、documents.text 或 AI 摘要。

- 跳转保存完整 URL，保留业务路径、查询参数和 SPA 路由。
- 关联复用 Documents.forUrl；同域不代表同系统，禁止仅按 host 传播别名。
- 多个书签可关联一个文档；多个快捷入口仍保留各自人工配置，不因文档合并丢名称。
- 多入口映射同一文档时可聚合检索别名，说明保持独立来源，不合成网页事实。
- 改快捷入口 URL 不改书签；改书签 URL 不静默改快捷入口，管理页提示关联变化供重绑。
- Documents.alias 是官方文档身份映射，不是用户别名。
- 配置随 Profiles 隔离；切换配置不得串用其他配置的人工信息与缓存。

## 6. 关键场景

| 场景 | 应有结果 | 禁止行为 |
| --- | --- | --- |
| 公司网站添加别名 007 | 保存后本地可查 | 要求网页先出现 007 或采到正文 |
| 两个入口都叫 007 | 提示并列出可辨认地址供选择 | 按频率默选或合并 |
| 网站需要登录 | @ 仍可打开；采集显示待登录 | 因采集失败删除快捷入口 |
| 只有个人说明，没有正文 | “报销”可找到入口，说明来源标为个人 | 编造额度、审批或流程 |
| 整理尚未确认 | 合格正文可入库，稍后补目录/标签 | 人工未操作导致正文长期不可检索 |
| 已入库后超时 | 保留旧正文，显示历史版本 | 删除或用错误页覆盖 |
| 删除最后一个关联书签 | 清理云端，独立快捷入口保留 | 将快捷入口当继续上传正文的默认授权 |

## 7. 自动化与变更通知

保留独立队列，将门槛放在各自业务入口，不等待所有队列清空。

| 变化 | 目标处理 | 上传影响 |
| --- | --- | --- |
| 新收藏、URL 变化 | 重建索引、解析身份、按配置采集并评估 | 合格新正文才上传 |
| 采集结果 | 成功更新内容；失败只更新尝试信息；重评资格 | 内容或资格变化时处理 |
| 标题/分类标签确认 | 主动刷新本地索引并 markDirty | 稳定上传字段变更须更新 |
| 目录移动 | 本地立即更新；短期同文档任务合并 | 当前上传含目录，仍需最终更新 |
| 人工名称/别名/说明保存 | 当前页刷新，其他页面收到配置事件后重建读模型 | 默认不上传个人字段，不重传 RAG |
| 登录/授权/手动重试 | 恢复对应采集任务 | 成功后再评估 |
| 失效复核到期 | 分批复核，持久化后续计划 | 确认失效才清理；删失败不标已清 |

公开抓取在 PageInfo 层合并进行中请求；不同 force、认证身份或采集方式不得错误复用。标题、标签、目录继续参与稳定上传指纹；没有独立元数据更新接口前，不承诺只改目录就完全不上传正文。

保存成功后当前页下一次查询应生效；其他页面收到配置事件后刷新。alarm 到期是执行机会，浏览器关闭、队列和服务故障都会延后，不是完成时限。

### 7.1 本地 VPN 与首尔服务的网络边界

用户经常使用 VPN，服务部署在首尔（用户提供的部署背景，未做实时检测）。本地抓网页、浏览器连首尔服务、服务端连上游必须分别诊断；timeout 只是当前请求超时，不能证明站点失效。共享链路疑似故障时按范围暂停，保留成功正文及人工信息，恢复后小量探测再放行。写入/删除超时可能已经生效，须核验而非自动重放。具体流程见 [RAG 设计第 4.1 节](rag-ingest-policy-design.md#timeout-network)。当前没有服务端代抓网页能力，不把首尔部署等同于浏览器采集成功。

## 8. 隐私、备份与恢复

1. 人工字段默认只用于本地匹配，启用 AI 短名或 RAG 不代表允许上传这些字段。
2. AI 短名维持现有标题、域名输入范围，不新增内部别名、说明或完整路径。
3. ? 默认在本地解析称呼，只将获准目标和正文用于模型上下文。若后续允许发送个人说明，须独立授权并标注个人来源，不能作为网页证据。
4. JSON 导出和完整配置备份是不同于 AI/RAG 的数据搬运。导出说明须列出个人字段；已有远端自动备份的新增字段须先确认范围扩展，未确认前不发送新增说明。既有名称/别名遵循既有备份范围，不追溯改变已有授权。
5. 合并导入遇同 URL 人工冲突保留本机并报告；替换需明确展示覆盖范围。未知新版本拒绝写回，避免旧客户端丢字段。
6. 备份保存人的配置；可重建缓存、临时任务和云端收据不是跨设备事实。恢复后按真实书签和身份重新关联。

现有接口只能用检索中的确切 ingest_hash 对写入完成作正向证明，检索未命中不能证明文档不存在。删除结果不确定，或首尔服务 rag_writes 处于 pending/uncertain 时，保持暂停并提示服务端核验，不自动清除服务端门禁；这是明确的人工处理分支。按 [服务端运维说明](../server/README.md) 核对集合、实际文档 ID 与内容版本后再恢复。没有新增服务端抓网页接口。
