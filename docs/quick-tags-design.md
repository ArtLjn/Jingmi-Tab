# 快捷入口（@）与个人称呼设计

> 版本 v1.1 · 2026-11-02 · 设计及工作区实现（待线上验收）
> 上位约束：[系统业务设计](bookmark-system-design.md)。代码核对基线：扩展 v1.16.0。
> 本版替代旧版方案比较与零散版本承诺，明确现状、目标和验收。

## 1. 定位与现状

@ 用用户熟悉的名字找到确定入口。网页摘要解释网页内容，人工信息表达“我怎么叫它、用它干什么”，彼此独立。

示例：原名“企业协同服务平台”，快捷名称“公司平台”，别名 007、OA，个人说明“公司内部入口，办理报销和请假”。@007 不依赖网站正文出现这个代号，也不依赖 AI。

| 维度 | 当前工作区静态核对 | 目标 |
| --- | --- | --- |
| 触发 | 首字符 @/＠；可关闭；已有键盘与 IME 处理 | 保留并回归 |
| 数据 | quick-tags.js 有 label、aliases、url、排序及使用记录 | 增加 note、updatedAt，让别名可编辑 |
| 编辑 | tag-manager.js 主要支持改名/排序/删除，面板可固定候选 | 管理页完整编辑，面板轻量编辑入口 |
| 匹配 | 别名混入 hay，排在名称与域名之后 | 人工精确别名优先 |
| AI | tag-suggest.js 从标题和域名建议短名 | 不覆盖人工信息，不猜内部代号 |
| 导出/备份 | 导出已有 aliases，完整备份包含 tags | 新字段贯穿所有保存恢复路径 |
| /、? | 未统一读取 QuickTags 的人工字段 | 工作包 B 增加只读关联 |

本表是改造前基线与目标对照；当前实现与测试位置见 [总设计第 11 节](bookmark-system-design.md#implementation-status)。旧文档未经本项目测量的使用率、命中率和收益数字不再作为决策依据。

## 2. 编辑与创建

| 字段 | 示例 | 规则 |
| --- | --- | --- |
| 网址 | https://portal.example.com/ | 必填 HTTP(S)，拒绝带登录凭据的 URL，保留业务路径/参数/路由 |
| 快捷名称 label | 公司平台 | 必填，去首尾空白，1–40 个 Unicode 码点 |
| 别名 aliases | 007、OA | 最多 20 条，每条 1–40 个码点，逐条增删 |
| 个人说明 note | 公司内部入口，办理报销和请假 | 可空，最多 500 个码点，独立于网页摘要 |

上限为首期设计约束，需实施时验证体验。数据入口与 UI 共用校验，超限报错，不静默截断。保存前预览“@007 → 公司平台 · portal.example.com”。保存成功必须表示落盘成功；失败保留表单和输入，不关闭、不提示成功。取消不写。

创建与发现：

- 候选固定可立即补个人信息，保留现有快捷固定；以后也能编辑。
- 工作台“快捷标签”在全部书签里搜索目标并添加别名/说明，不提供脱离书签的“新建入口”；已在书签里标注过的目标直接进入编辑。面板提供进入同一编辑流程的动作。
- @007 无结果时显示“为 007 绑定一个入口”，用户选择书签/候选或填写网址后显式保存别名，不把 007 当域名，不让 AI 猜 URL。
- 完整网址的现有新建并打开路径保留，稍后可补别名。
- 同 URL 再创建，定位已有记录供编辑，不静默忽略新填写的别名。
- 修改快捷 URL 显示新旧目标及关联变化，不同时改浏览器书签。

## 3. 匹配与歧义

### 3.1 标准化

保留展示原文。匹配副本使用 Unicode NFKC、去首尾空白、连续空白折叠、大小写折叠。不转数字，007 不等于 7；不将别名按 URL 解析。拼音生成、模糊纠错、路径补全不在本轮承诺中。

### 3.2 非空查询排序

1. 完整目标 URL 精确匹配。
2. 人工名称或人工别名精确匹配。
3. 人工名称或别名前缀匹配。
4. 人工名称/别名包含及已有词首缩写匹配。
5. 域名、原始标题等系统信息匹配。
6. 个人说明包含匹配。

匹配等级先于频率；同级再按现有频率、手工顺序、稳定 ID 排序。高频域名候选不能压过人工精确别名。空查询保留已有固定、AI 建议、常用候选分组和频率逻辑；首屏上限不等于可维护记录上限。

### 3.3 重名

- 同记录内按标准化值去重；与名称相同的别名提示冗余，不重复保存。
- 不同目标可有相同名称或别名；保存时提示冲突地址，不强制覆盖另一记录。
- 所有精确冲突项可见，不被固定区展示上限静默隐藏；显示域名，必要时显示路径和说明。
- 多个精确目标时提示“多个入口使用此称呼，请选择”，初始不高亮可打开项。直接回车只提示选择，用户用方向键或点击选中后才打开。
- 异步刷新保持已选目标，不改变回车指向。
- 自动候选可按 host 去重；人工入口不得按 host 合并，同域 /oa 和 /finance 可分别叫 007、财务。

## 4. 模型与模块

复用 QuickTags 人工记录；新增 note、updatedAt，不建立第二套个人信息库。

```json
{
  "id": "tag_example",
  "label": "公司平台",
  "url": "https://portal.example.com/",
  "host": "portal.example.com",
  "aliases": ["007", "OA"],
  "note": "公司内部入口，办理报销和请假",
  "pin": 0,
  "hits": 0,
  "lastUsed": 0,
  "createdAt": 0,
  "updatedAt": 0
}
```

| 模块 | 责任 | 边界 |
| --- | --- | --- |
| quick-tags.js | 校验、标准化、匹配、冲突查询、CRUD、迁移与落盘 | 不依赖 DOM、采集、RAG |
| tag-manager.js/newtab.js | 表单、预览、反馈、选择与调用保存 | 不另存一份人工信息 |
| personal-targets.js（只读检索投影） | 通过 Documents.forUrl 映射人工记录与书签/文档 | 不按 host 扩散，不修改正文或跳转 URL |
| content-index/documents 消费端 | 本地可搜索字段增加人工信息，保留来源 | 不将 note 写入 text/desc |
| bookmark-search/bookmark-answer | 本地解析称呼，按获准正文回答 | 个人说明不能当网页证据 |
| backup/Profiles | 版本、配置隔离、授权范围和恢复 | 不把 RAG 授权当备份授权 |

@ 独立本地可用。/ 仅增加已有书签的匹配字段；? 可返回独立快捷入口，无正文只展示入口。人工编辑默认不改变 RAG 指纹，不触发个人信息上传。

## 5. 数据完整性与隐私

1. 保持现有存储键，提升内部数据版本。读取旧版本给 aliases/note 补空，保留已有 ID、URL、别名、顺序与使用记录。
2. 旧客户端不能将未知新版本 normalize 后剥字段写回；不支持时拒绝写入并提示升级。
3. 更新只改提交字段和 updatedAt，不重置频率/顺序；并发编辑用记录版本检测，冲突交用户处理。
4. 候选固定、删除撤销、snapshot/restoreState、JSON 导入导出、完整备份恢复均须保留新增字段。
5. 同 URL 导入人工字段冲突：合并保留本机并报告，替换明确展示影响范围；未知新版拒绝写回。
6. 删除快捷入口不删书签/缓存/云端；清空学习记录不删人工字段；网页重采、AI 重生成、RAG 清库不影响人工字段。
7. 人工字段默认本地，AI 短名仍只用候选标题与域名；? 默认本地映射，不自动发送别名或说明。
8. 本地导出告知范围；既有远端自动备份新增说明前需范围扩展确认，未确认前不上传 note。既有名称/别名继续遵循既有备份配置。详见总设计第 8 节。

## 6. 验收与交付

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| QJ-01 | 网页名称没有 007 | 别名精确命中，优先于高频域名包含 |
| QJ-02 | 无 AI、离线、登录墙 | 仍可查人工入口并发起打开，网络加载另行反馈 |
| QJ-03 | 网页重采、AI 换短名 | 人工信息不变 |
| QJ-04 | 007/7、全角、大小写、中文输入法 | 前导零保留，标准化一致，组合输入不误跳 |
| QJ-05 | 两目标同叫 007 | 提示并显示全部精确候选，直接回车不误开 |
| QJ-06 | 同域多路径/业务参数/SPA 路由 | 配置分别保留，目标地址不误合并 |
| QJ-07 | 编辑重载、撤销、导出、备份恢复 | 字段不丢，保存失败不报成功，冲突可报告 |
| QJ-08 | 多页面、配置切换、旧版升级 | 不串配置，不盲覆写，不丢原数据 |
| QJ-09 | /007、?007 怎么报销 | / 仍限书签；? 无正文不编流程 |
| QJ-10 | 普通搜索、关闭 @、原键盘操作 | 行为保持；不向网页联想接口发送内部代号 |

工作包 A 交付编辑、匹配与完整性（QJ-01 至 QJ-08、QJ-10）；B 交付统一读模型及证据隔离（QJ-09）。沿用 tests/quick-tags*.test.js、管理页浏览器、搜索、备份及配置测试。表格是验收要求，工作区实现与测试位置见总设计第 11 节。
