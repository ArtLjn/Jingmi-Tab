# RAG 收录、异常处理与恢复设计

> 版本 v1.1 · 2026-11-02 · 设计及工作区实现（待线上验收）
> 上位约束：[系统业务设计](bookmark-system-design.md)。代码核对基线：扩展 v1.16.0。
> 本版替代 v1.0 相互冲突的状态和示例代码，统一保护、删除、重试与恢复。

## 1. 业务目标与现状

当前 SyncEngine.process 首次采集失败且无收据时仍可能调用 Rag.upsertDocument，只有标题、URL、目录的骨架也会入库并显示已同步。有收据时已有提前返回保护，但有 docId 不代表旧正文合格。

目标：主集合提供有内容依据的问答来源，入口发现由本地搜索和个人称呼补足。保存书签、云端入库、可作回答证据是三个不同结果。

| 目标 | 验证标准 |
| --- | --- |
| 新失败不污染主集合 | 无合格旧正文的超时、登录墙、空壳不调用 ingest |
| 临时失败保护历史内容 | 成功正文、内容 hash、已上传版本不变，只更新采集尝试 |
| 清理结果真实 | 删除成功或确认不存在后才标已移除；失败保留恢复任务 |
| 页面恢复能补入 | 主动巡检、人工采集、权限事件可恢复，不靠 revision 自己变化 |
| 入口独立可找 | 007 别名与导航页本地可查，不受正文收录状态控制 |

本期不新增后端接口，不承诺跨设备元数据搜索，不把个人说明或 AI 摘要当网页正文，不重写 RetryPolicy 的既有错误分类。

静态核对：documents.contentVersion 排除了时间和错误；RetryPolicy 对 404 停止、权限问题暂停；Rag 已有写租约与收据；上传文本包含目录和分类标签。检索服务 top_k 60、客户端最多 30 文档、回答最多 6 证据。读取后过滤不能补回所有被挤掉候选，但污染程度与收益需实测，不用词频密度推导确定收益。

## 2. 分离三个状态维度

以下为本次新增字段，不能据此推断旧版本已有这些字段；工作区已实现并由策略版本触发协调。

| 维度 | 字段及状态 | 含义 |
| --- | --- | --- |
| 本次采集 | 保留 captureState/captureNote/checkedAt 等 | 这次取到了什么，为什么失败 |
| 收录决策 | admissionState：eligible / metadata / deferred / invalid / excluded | 按当前内容和授权应如何处理 |
| 云端事实 | syncState：pending / synced / deleting / deleted / excluded / failed / paused | 网络操作实际到哪一步 |

metadata 是“仅本地入口”，本期处理完成，不长期 pending。deferred 可保留云端旧版，不等于云端无记录。invalid 是失效判断，不等于删除已经完成。独立快捷入口不使用这些状态控制存在性。

新增计划信息：admissionReason、reviewDueAt、404 candidate 的 firstSeenAt/lastSeenAt/count、recoveryDueAt、policyVersion。失效时间与首次疑似失效时间分开，不复用字段。记录已上传版本及资格，receipt 存在本身不能证明旧版合格。jobs 继续保存执行状态、attempts、nextAt、generation、lease；尝试次数不进入内容版本。

## 3. 正文门禁

判断顺序：

1. 检查真实书签引用、删除状态、上传授权与私有策略；授权撤销优先于历史保护。
2. 区分本次成功内容与残留历史内容；失败记录里有长文本不等于本次成功。
3. 分别评估新正文资格和历史已上传正文资格。个人说明、AI 摘要、标题、URL、目录、标签不计入网页正文。
4. 输出新入库、保留旧版、仅本地、等待条件、复核或清理决策。
5. 网络写前重验授权、文档版本与引用；旧任务不能发布新版本终态。

撤销“少于 200 字符一律不入库”的硬规则，字符数仅用于观察与可疑内容提示。

- 有可识别信息的真实正文，无登录墙、错误页、动态壳信号，可评估 eligible；短操作说明不按字数自动排除。
- 只有标题、导航或站点 description，以及明确 no_content，先作 metadata，不把 desc 自动当正文。
- description 可能有实际价值，但首期需来源确认或补采才升级，不凭长度通过。
- capture/feishu_api 获准后按真实内容和来源判断，不因短或跳过自动采集误伤，也不能绕过上传授权。
- 采集结果不足以确定页面类型时，转 deferred 等补采，不自动删除合格旧版。

规则先用样本验证，再固化为无 IO 的纯决策函数，不要求先建质量评分模型。

## 4. 异常决策表

“旧版”均指已确认有合格正文的云端版本。

| 场景 | 无合格旧版 | 有合格旧版 | 后续 |
| --- | --- | --- | --- |
| 正文可用 | eligible，安排上传 | 内容变化才上传 | 指纹不变不传 |
| 确认仅导航/无正文 | metadata，仅本地 | 保留旧版、提示待复核 | 确认真实正文撤除才可清理 |
| 源站采集 timeout/network | deferred，先诊断本地链路 | 保留旧正文、记录尝试 | 先区分 VPN/本机、目标站和未知，不直接耗尽单站重试预算 |
| 源站 408/5xx | deferred，不入库 | 保留旧正文 | 记录来源与响应，有限重试；不归因为本地 VPN |
| 429/daily_limit | deferred，暂停请求 | 保留旧正文 | 按既有恢复条件或可信服务提示恢复 |
| 401/403/login_wall | deferred，等待登录 | 保留旧正文 | 登录/打开采集事件，不盲目定时撞墙 |
| waiting_permission/waiting_auth | deferred，等待授权 | 保留旧正文 | 权限/认证变更触发 |
| dynamic_shell/waiting_open | deferred，等待可读内容 | 保留旧正文 | 打开采集或换适配器，不把等待 7 天当解决办法 |
| client_blocked | deferred，提示检查拦截 | 保留旧正文 | 排除拦截后单项重试 |
| 首次 404 | deferred，记候选、不上传 | 保留旧正文，记复核计划 | 最早 24 小时后绕过失败缓存复核 |
| 间隔至少 24 小时仍 404 | invalid，无云端记录无需删 | invalid，安排删除 | 删确认后标已移除，保留主动恢复 |
| 可信 410 | invalid | invalid，安排删除 | 无需 404 等待窗口，恢复机制仍保留 |
| 400/422 | deferred，停同样请求、检查参数 | 保留旧正文 | 请求错误不作为页面永久消失证明 |
| unsupported/not_html | metadata，说明当前不支持 | 保留旧正文 | PDF 等不支持不等于死链，适配器升级可再采 |
| 撤销私有上传授权 | excluded，不上传 | excluded，安排清理 | 删除失败可见可重试，本地按原授权保留 |
| 删除最后书签引用 | 不上传 | 安排清理 | 独立快捷入口不是继续上传正文的授权 |

必须区分错误来源：源站 404 才参与页面失效复核；RAG DELETE 404 仅说明云端不存在；RAG ingest 的 400/422 不能判源网页失效。409 写入结果不确定时暂停写入、删除与自动重发，先核验。

### 4.1 timeout：VPN 场景下的链路诊断

部署背景来自用户说明：经常使用 VPN，服务部署在首尔。该背景用于诊断优先级，不是实时健康证明；本次没有连接服务器或修改 VPN。服务器部署正常也不代表浏览器到首尔的链路、服务器到上游的链路和每个请求都正常。

当前 PageInfo 在浏览器本地 fetch 源站；Rag.request 从浏览器请求配置的 RAG/账号代理；账号代理再请求上游 RAG。它们共用 timeout/network 名称，必须新增来源上下文，不能把所有超时都记到网页身上。

| 环节 | 可能原因与判据 | 业务处理 |
| --- | --- | --- |
| 浏览器 → 源站 | 本地网络、VPN 路由、代理规则、DNS/握手、目标慢、扩展拦截等；浏览器常不暴露足够细节 | capture timeout，页面存活状态 unknown；保留内容，先诊断 |
| 浏览器 → 首尔服务或实际 RAG 地址 | 本地/VPN 链路、目标服务、代理或等待处理；确认实际请求终点 | 暂停该服务范围同步，不把文档标采集失败，不重抓已有成功正文 |
| 首尔代理 → 上游 RAG | 通过服务端请求 ID、阶段耗时、上游错误确认 | 归类服务端/上游异常，不自动责怪本地 VPN |
| 入库/删除已发送但客户端超时 | 服务端可能仍完成操作 | outcome_unknown，保留操作标识并核验，不能按普通网络错误自动重放 |

诊断步骤：

1. 先记录 operation（capture/retrieve/ingest/delete）、请求来源 local/server、目标 origin、预算、elapsed、是否收到响应、requestId（如有）。日志不记录 token、完整私有 URL 参数、别名或说明。浏览器未知 DNS/代理细节就保持 unknown，不编造根因。
2. 在同一操作路径下合并一次低频、只读、无副作用的服务探测。账号服务已有 /health，只能证明该账号服务端点可达；/health?deep=1 检查数据库，不证明 RAG 或源站可用。自定义 RAG 地址没有合适探测接口时用最近可信请求和手动检测结果，不发明健康接口。
3. 服务探测失败且多个不同源站短时间一起失败，是本地/VPN 链路异常的线索，标 network_suspected，暂停相关网络范围任务并提示检查网络/VPN；不是已证明 VPN 故障。单一源站超时但服务可达，仍只能说源站访问路径有问题，分流 VPN 也可能造成这种现象，不能直接判源站宕机。
4. 优先复用近期健康结果，不为每条失败书签额外打探测请求；浏览器 online 事件、服务再次可达、用户点击“网络已恢复，重试”可唤醒队列。online 本身不证明 VPN 链路已恢复，恢复后先用少量只读请求试探，再逐步放行，避免批量重放。
5. 首轮诊断未明时暂停/延后并显示原因，不记 404 计数，不写 invalid，不删除云端，不消耗站点永久失败预算。链路确认可用后，真实单站超时才进入有限退避；共享链路故障按范围退避，已知正常的其他链路继续运行。

浏览器通常不能可靠读取 VPN 开关、节点和路由；不新增宽泛权限监视 VPN，也不自动开关 VPN、修改系统代理或选线路。用户报告切换 VPN 作为诊断线索，实际链路恢复由低频试探确认。

超时预算按操作分层，不把本地抓取、retrieve、ingest、delete 共用固定时长。源码当前 retrieve 默认约 5 秒、ingest 20 秒、DELETE 15 秒，而账号代理上游 timeout=30 秒，替换还可能先删再写；客户端先中止可能形成结果不确定。实施前核对线上代理/网关实际预算和各阶段耗时，再协调总预算、取消和幂等核验机制，不能仅增加重试次数或无限延长超时。

服务端对照属于可选诊断能力，不是当前已实现的抓网页后备通道。可先对同一 requestId 查看首尔服务日志区分到达、排队、上游、完成。若以后引入服务端公开网页采集，需单独设计接口与用户授权，禁止转发浏览器 Cookie，限制 SSRF、私网地址和跨重定向访问；服务端可达不证明用户本机也可达。

## 5. 保护、复核与恢复

### 5.1 保护及例外

临时失败、权限不足、采集器不支持、单次空采，不得改写或删除合格旧正文及其内容 hash、已上传版本。

允许清理：确认失效、确认正文真实撤除、授权撤销、最后书签引用删除、经审计确认的历史污染。必须显式安排清理任务，禁止 gate 拒绝就无条件 removeDocument。

### 5.2 404 双次确认

首次记录 candidate、reviewDueAt 至少晚 24 小时。只有实际新请求才能增加确认次数，同一失败缓存或同一请求的多处消费不算复核。到期仍 404 才判 invalid；成功清候选并评估正文；变成超时/403 不算第二次 404，转相应等待。

已有登录、私有或身份差异线索时先恢复条件，不能多次匿名 404 就自动判死。24 小时是保守初始值，双次确认仍可能误判，需观察实际样本。

“确认正文撤除”须是可核验的成功来源或人工明确确认，单次 no_content、不支持或抽取器升级失败不足以成立。

### 5.3 主动恢复

invalid 保留 recoveryDueAt，初始建议每 7 天有界复核，按资源配额分批执行；必须主动发起新采集，不能只等缓存更新。手动补采、权限事件可提前触发。

成功后清候选、重评资格、安排 upsert；HTTP 成功但仍无正文只转 metadata，不标已入库。相同 URL 可自动恢复，变 URL 重解析身份；已删除引用或授权未恢复不得重新上传。

到期表示允许尝试，不是完成时限。浏览器关闭、离线、服务暂停及配额都会延后。

## 6. 唯一调度与并发一致性

jobs.nextAt 是唯一执行时钟。RetryPolicy 决定同轮短重试；IngestPolicy 决定收录及后续业务复核。reviewDueAt/recoveryDueAt 由 reconcile 转为任务，不与 finish 竞争写 nextAt。

| 情况 | 计划 |
| --- | --- |
| 源站网络超时 | 先执行第 4.1 节诊断；共享链路故障按范围暂停，不逐条扣站点失败预算；确认可重试后有限退避 |
| 源站 408/5xx | 保留既有短重试预算，耗尽后建议 2 小时开启有界新一轮 |
| RAG 写入/删除超时 | 结果不确定，先核验操作是否完成；禁止盲目重放 |
| 限流/日额度 | 既有恢复条件，或可信恢复时间 |
| 登录/授权/动态壳/请求参数错误 | 条件事件或用户单项重试，不同条件不盲重放 |
| 首次 404 | 到期是新的业务复核，不受 classify 的 stopped 永久阻挡 |
| invalid | 到期产生恢复任务，先检查引用及授权 |

finish 接收显式“短重试、等待条件、业务复核、完成、写入不确定”结果，不能再只凭 retryable 布尔值推导终态。业务等待不显示成传输失败。

网络删除与 IndexedDB 不能由本地事务原子提交。采用持久化操作意图：

1. 写删除意图，保存集合、实际云端 docId、目标版本、原因、generation、授权范围；云端状态 deleting。
2. 取得并重验租约，发送前检查意图仍有效；网络请求在数据库事务外执行。
3. DELETE 成功或确认 404 后按 generation 更新状态并清收据；失败保留意图，不提前标 deleted。
4. 同文档串行协调；旧删除不能在新 upsert 后执行。删除已发出时先明确结果，再重建最新获准正文；过期任务不发布新终态。
5. 重启/租约过期按意图幂等续跑；409 等不确定结果先核验，不盲删再写。

## 7. 检索、展示和个人信息

写侧为主，读侧防旧污染和竞态。历史失败骨架不能作正文证据；候选仍校验真实书签、账号/客户端范围、URL、docId、版本和授权。

临时失败保留旧版时，不能仅按最新 captureState=failed 过滤旧正文；新采集尚未上传也不能只凭本地 hash 不同排除旧成功版本，要对照已上传版本及资格。失效待删除内容立即从本地问答证据隔离，删除失败单独提示。

| 展示 | 业务含义 |
| --- | --- |
| 正文已入库 | 合格正文获云端确认 |
| 使用历史正文，本次采集失败 | 旧成功版本可用，不保证目标网址此刻可访问 |
| 仅保存入口，未收录正文 | metadata，本期处理完成 |
| 暂未收录，等待重试/登录/授权 | deferred，显示下一动作或计划 |
| 页面疑似失效，等待复核 | 首次 404 |
| 页面已失效，云端清理中/清理失败 | invalid，删除未确认 |
| 页面已失效，已从知识库移除 | invalid 且已确认删除；本地入口保留 |
| 已停止上传，云端清理中 | 授权撤销，尚不能称已清除 |

@007 不经过正文门禁；/007 读取本地关联别名。开启 RAG 同步后，关联书签的人工名称、别名和 note 可作为用户资料单独收录，使用 record_quality=personal、coverage=personal、user_annotations 标记来源，不计为正文。?007 怎么报销 可依据备注识别入口和个人用途，但 note 不是网页流程证据，具体操作仍需正文支持。修改人工字段参与版本更新；删除人工资料后，保留合格正文或清理仅人工资料的记录。私有正文开关只控制网页内容，不能阻挡已授权的人工资料同步。

二期元数据云端通道须先确认接口能力，再设计集合、来源、合并与授权；不能只凭主集合结果数量决定导航意图是否满足，也不能将元数据通道混成正文证据。

## 8. 历史治理、灰度与回滚

先阻止新增污染，再处理历史数据：

1. 影子审计只记拟决策，不改云端；区分失败骨架、合法短正文、私有内容与无法核验记录。
2. 输出可审查清单：本地身份、实际 docId、集合、已上传版本、理由及动作。
3. 清理明确启用后分批执行；无来源和资格证据者保留并报告，不按标题或长度盲删。
4. 记录 ingest/DELETE 成功、失败、跳过、冲突、恢复计数；中断可续跑，重复执行安全。
5. 自动失效删除与主动恢复共同交付；恢复未验收前不启用自动失效删除。

建议 observation、ingestGate、cleanupEnabled 分开，默认清理关闭。门禁异常可停新写，清理异常可停新删；已删除内容不能靠配置开关撤销，需合格本地快照或重新采集重建并获服务确认。隐私排除不得因回滚重新上传；不把 legacy 失败骨架重新入库当正常回滚方案。

## 9. 模块、分期与验收

| 模块 | 责任 |
| --- | --- |
| ingest-policy.js（收录纯策略） | 依据来源、正文、失败、旧版资格和授权输出决策，不做 IO |
| Documents | 身份、成功内容、尝试、收录决策、上传版本及读模型 |
| SyncEngine | 业务计划转任务、去重、租约、删除意图、重试与版本协调 |
| Rag | 执行经复核操作、保留真实收据、校验检索；gate 拒绝不等于删除 |
| PageInfo/CaptureAdapters | 来源可区分，复核绕缓存，安全复用进行中请求 |
| 界面与统计 | 联合状态、下一动作、来源与真实侧效应计数 |

工作包 C 先交付非破坏性门禁、旧成功保护和影子统计；D 共同交付复核、清理、恢复巡检及历史治理。与总设计顺序一致。

| 编号 | 必测场景 | 断言 |
| --- | --- | --- |
| RI-01 | 首次超时/登录墙 | 无 ingest、无无条件 DELETE，本地入口可查 |
| RI-02 | 旧正文遇失败/不支持/空采 | 正文 hash 和已上传版本不变 |
| RI-03 | 短有效正文、长登录页 | 不以 200 字符代替资格判断 |
| RI-04 | 缓存 404、到期 404、复核改 403 | 仅新请求累计，满足时间才判失效，403 转等待 |
| RI-05 | 源站错误与云端错误 | 请求错误不误判源站死链，DELETE 404 幂等完成 |
| RI-06 | 删除失败/中断/重复 | 未确认不标已清，实际 docId 保留，可恢复 |
| RI-07 | 新正文与删除竞态、过期租约/generation | 旧任务不覆盖，最新获准正文最终可用 |
| RI-08 | invalid 恢复但缓存无新 page | 主动新采集，不等待 revision 自变 |
| RI-09 | 撤权、最后引用删除、独立快捷入口 | 不复活上传，清理失败可见，入口不丢 |
| RI-10 | 骨架 receipt、合法短文、未知旧数据 | 不把 receipt 一律当成功，不盲删 |
| RI-11 | 409 写结果不确定 | 暂停核验，不自动重发/删除 |
| RI-12 | 007 别名、仅个人说明 | 可定位，不作为网页事实 |
| RI-13 | 现有搜索、重试、私有/飞书权限 | 原边界不回归，新策略显式适配分类 |
| RI-14 | VPN/本地链路异常，多源站同时超时 | 合并探测、按范围暂停；不逐条耗尽站点预算，不判失效，不删内容 |
| RI-15 | 首尔服务可达但单站超时，或首尔上游超时 | 可达性分层，不将 health 成功当源站/RAG 业务成功；保留 unknown 或上游归因 |
| RI-16 | 客户端先超时，服务端随后入库/删除成功 | 标结果不确定并核验；不重复写入，不误删新版本 |
| RI-17 | VPN 切换、online 事件、批量恢复 | 先小量只读试探，逐步放行，不自动切 VPN、不放大请求 |

沿用 tests/rag.test.js、pipeline.test.js、retry-policy.test.js、capture.test.js、搜索及浏览器测试，新策略模块补对应单测。表格是实现验收要求，工作区结果见总设计第 11 节；不代表线上已通过。

观测新增不合格入库数、旧版保留次数、实际复核请求、清理成功/失败/冲突、恢复到期/完成、导航查找成功率与问答正文证据比例。先测基线再定阈值，不承诺请求总量必降或固定精确率收益。
